## 8C.9 — état transitoire au bootstrap

Le workflow 46088496681 du commit 68a61fd échoue désormais avant toute écriture : le snapshot local contient 26 catégories neutres et manque six des neuf catégories réelles, contrairement à la réinjection précédente qui contenait aussi les neuf réelles. Les marqueurs sont présents en base, les contrôles PostgreSQL passent. Hypothèse étayée par le code : le client historique relance le bootstrap à INITIAL_SESSION / SIGNED_IN, appelle switchHouseholdCache (seedState) et ne remet pas immédiatement cloudSyncReady à false. Le test précédent attendait uniquement ce drapeau. V3.1 ignore désormais les événements Auth redondants sur un foyer déjà hydraté, baisse le drapeau dès le début d'un bootstrap et refuse les pushes pendant ce chargement. Le test historique, sans changer le code épinglé ni ses données, attend une session réellement stabilisée (foyer attendu, promesse terminée, baseline et digest cohérents) puis contrôle les mêmes catégories/budgets et écritures. Il journalise aussi les listes locales et le baseline fictifs par version. Il ne supprime aucune assertion ; la cause exacte et la coexistence doivent être confirmées par la nouvelle CI. Les risques propres à un ancien client déjà distribué ne sont pas éliminés par le correctif V3.1.
